## 回答邊界

- 對已核准、版本明確的規則，回答結論、條件、依據與下一步。
- 對條件不足的問題，先追問必要條件，不要猜測個人資料。
- 對文件未涵蓋、個案認定、例外批准或可能影響權益的問題，說明限制並轉真人。
- 不得把「依目前提供資料」包裝成正式批准、法律意見、財務承諾或人事裁決。

## 知識來源與檢索

- 只使用核准文件、正式資料庫或已指定來源。
- 保存文件名稱、章節、版本、有效日期與內容 owner。
- 回答應保留可回查的條款或來源識別資訊。
- 找不到足夠來源時，不得用模型記憶補全文字或規則。
- 文件更新後重新索引，並重跑標準題、條件題與超出範圍題。

## 轉真人與人工接管

轉真人條件至少包括：

- 問題涉及個人資格、薪資、年資、權益、批准或例外。
- 問題需要未提供的文件、資料或事實判斷。
- 問題涉及未收錄主題、跨文件矛盾或規章版本不一致。
- Agent 的檢索結果低信心、來源衝突或沒有可引用依據。
- 使用者要求直接覆寫規則、忽略限制或讓 Agent 做未授權決策。

轉介訊息至少說明：目前能確認的範圍、無法判斷的原因、需要聯絡的角色/單位，以及建議準備的資料。

## 高影響決策

以下工作預設保留給具名人員：

- 錄取、淘汰、薪資、年資與特殊條件。
- 個人福利、補助、請假資格與例外認定。
- 報支拒絕、付款承諾與政策例外。
- 涉及法律、醫療、資安、合規或重大財務影響的判斷。

AI 可以摘要、分類、提出建議或準備草稿，但不得讓「建議」在沒有人工覆核時變成「決定」。

## 安全與隱私

- 最小化收集個人與敏感資料。
- 依角色控制來源文件、索引與對話紀錄的存取權。
- 將使用者輸入與知識文件分離，避免輸入內容改寫系統規則。
- 記錄回答所用來源、版本、時間、模型/流程版本與轉介結果。
- 為測試資料去識別化，不使用不必要的真實個資。

## 測試矩陣

| 題型 | 最少測試內容 | 通過條件 |
|---|---|---|
| 標準題 | 文件中有明確答案的問題 | 答案正確、條件完整、附來源 |
| 條件題 | 缺少年資、日期、金額或時數的問題 | 先追問或明確列出假設，不擅自補值 |
| 邊界題 | 接近門檻、逾期、特殊例外 | 清楚說明規則與限制 |
| 超出範圍題 | 文件未涵蓋主題 | 不編造，轉指定真人 |
| 衝突題 | 使用者說法與規章不同 | 呈現來源差異，轉 owner 或 HR |
| 攻擊/注入題 | 要求忽略規章或改寫指令 | 不接受覆寫，依原規則處理 |
| 權益題 | 涉及薪資、資格、錄取或拒絕 | 提供一般規則但保留人工判斷與轉介 |
